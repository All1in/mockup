# Задача 2: Автоматичний refresh токена (45 хв)

**Стек:** React + TypeScript, Vite, react-router-dom. Для HTTP — нативний `fetch`, ніяких axios.

## Мета

Access token живе 15 хвилин. Зробити щоб він оновлювався сам, без участі юзера.

## Крок за кроком

### 1. Таймер — основний механізм

- Після логіну/реєстрації бекенд повертає `expiresIn` (секунди до смерті токена)
- Ставимо `setTimeout` на `(expiresIn - 60) * 1000` мс (за хвилину до протухання)
- Коли спрацював — `POST /auth/refresh` → отримали новий `expiresIn` → ставимо новий таймер
- При логауті — `clearTimeout`

### 2. Перехоплення 401 — страховка якщо таймер не встиг

- В `api.ts`: якщо відповідь `401` → `POST /auth/refresh` → повторити той самий запит
- Якщо refresh теж повернув помилку — розлогін (очистити user), не пробувати знову

### 3. Одна черга — щоб не було зайвих запитів

- Змінна `refreshPromise = null`
- Перший 401 створює `refreshPromise = fetch('/auth/refresh')`
- Другий і третій 401 бачать що Promise вже є — чекають його
- Коли завершився — `refreshPromise = null`

## Важливо

- Фронт НЕ зберігає і не читає токени — тільки каже бекенду "онови" через `POST /auth/refresh`
- `expiresIn` зберігати лише для розрахунку таймера, це не секрет
- Таймер — основний механізм, 401-перехоплення — fallback

## Тестування

Використай короткі TTL при логіні:

```json
POST /auth/login
{ "email": "test@example.com", "password": "Password123!", "accessExpiresIn": "30s", "refreshExpiresIn": "2m" }
```

## Перевіряємо

- [ ] Сиджу на сторінці 30+ сек → токен оновився сам, нічого не помітив
- [ ] Логаут → таймер не спрацює після виходу
- [ ] Обидва токени протухли → бачу розлогін, сторінка не зависла
- [ ] 3+ паралельні 401 → лише один `POST /auth/refresh`
